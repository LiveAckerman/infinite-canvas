  - 编排：
    - 最多 10 步；超过点「添加步骤」会被拦下并 toast「最多 10 个步骤」。
    - 同一个角色可以在一条流水线里出现多次（场景：连续两次精修）；切换某步的角色不影响其它步。
    - 拖拽换序：抓步骤卡左上 grip 把手左右拖，松开后顺序变更；运行中 grip 变灰禁用。
  - 数据流：
    - 在「原图 seed」卡上传一张图 → 第一步的「输入图」缩略图自动显示这张图，标签「来自原图」；
    - 第一步跑完产物后，第二步的输入图缩略变成第一步的产物，标签「来自步骤 1」；
    - 每步的「替换输入」按钮：点击上传一张新图 → 该步输入变成手动覆盖（橙色 Pencil 图标 + 标签「手动替换」）；点「用上游」可恢复成上游产物。
  - 单步重做：
    - 已完成的步骤上点「重做」会重跑该步，pill 变蓝色「运行中」→ 跑完变绿色「已完成」；
    - 上游某步重做完产物变了，下游已完成的步骤 pill 自动变金色「上游已变更」，输出图右上角出现琥珀「已变更」徽标，按钮文案变成「用新输入重做」；
    - **下游不会自动重跑**，必须用户手动点该步的「重做」才传播。
  - 顶部智能运行按钮：
    - 全部 idle → 「▶ 运行流水线」从第 1 步开始顺序跑；
    - 第 3 步失败 → 第 4 步及之后保持 idle，按钮文案变「▶ 从第 3 步续跑」；
    - 全部 success 且无 stale → 「▶ 全部重跑」；
    - 全部 success 但第 2 步 stale → 「▶ 从第 2 步续跑」。
    - seed 没传或 0 步骤时按钮 disabled。
  - 错误处理：跑到中间某步失败，pipeline 暂停在该步，红色错误条 + 单步「重试」按钮；用户修完原因（改输入图 / 改附加说明 / 等模型恢复）点重试，能继续跑后续。
  - 角色被删：保存后把该流水线里某步用到的角色从「我的角色」删掉，再回流水线模式打开这条流水线，那一步显示红色 Tag「角色已删除」+ Select 是空；运行整条流水线时该步会变成「失败」并提示「角色不存在或已被删除，请替换为其它角色」。
  - 单步产物的「下载 / 加入素材」按钮在该步完成后可见，跟工作台一致；「加入素材」的素材 category 是「流水线」。

- 参考图上限 9 张：
  - `/image` 工作台或角色工作台传 9 张参考图 → 正常生成。
  - 传 10 张及以上 → 返回「参考图数量超过上限（最多 9 张）」。

- 后端业务错误透传到 UI：
  - 把测试账号的 `credits` 改成 0（或本来就是 0），点开始生成。
  - 后端返回 `{code:1, msg:"额度不足，请联系管理员"}`。
  - 前端 UI 应该看到：① 失败卡片标题「生成失败」+ 正文 **「额度不足，请联系管理员」**（**不是**「请求失败」）；② 顶部 toast 也是「额度不足，请联系管理员」；③ DevTools Console 有一行 `/api/v1/images/generations 失败 {code:1, msg:"额度不足..."}` 方便复盘。
  - 同理：让后端 ai-config 没配置启用 → 返回「未配置启用的模型，请联系管理员」；故意上传一个超大请求触发 nginx 413 → 显示「请求体过大」中文提示；故意断网 → 显示「请求失败」（这是网络层兜底，不是业务错误，符合预期）。
  - `/agents` 角色工作台并行模式 / 流水线模式调上游失败时同样规则：业务 msg 直接显示给用户，不再降级。
- 生图额度并发扣减（reserve-then-confirm）：
  - **常规扣减**：用户余额 5，点一次生图（n=1）→ 余额变 4，`/admin/credit-logs` 一条「-1 → 4」流水；连点 5 次直到余额 0 → 流水从 5 → 4 → 3 → 2 → 1 → 0 完整。
  - **预扣 + 退回**：用户余额 5，触发一次生图 n=3 → 立刻预扣 3 → 余额 2；上游正常返回 3 张 → 不再扣（已经预扣过）→ 流水「-3 → 2」。
  - **上游失败退回**：用户余额 5，触发 n=3 → 预扣 3 → 余额 2 → **断网 / 上游 5xx / 上游返回 0 张** → 应自动退回 3 → 余额回到 5，**不写流水**。前端 toast「上游服务异常」或「请求失败」。
  - **部分返回退回**：用户余额 5，请求 n=3 但上游只回来 1 张 → 退回 2 → 余额 4 → 写流水「-1 → 4」。
  - **并发抢扣**：用户余额 **1**。打开 3 个 tab 同时点「开始生成」（或一个 tab 连点 3 次「开始生成」） → 应只有 1 个 tab 成功（流水「-1 → 0」+ 收到图），其它 2 个 tab 应返回业务错误 **「额度不足，请联系管理员」**（流水里**不会**多出 2 条「-1 → 0」的伪记录）。
  - **额度 0 拦截**：用户余额 0，curl POST `/api/v1/images/generations` → 应直接返回「额度不足，请联系管理员」，**不调上游、不写流水**。
  - **admin 不参与**：admin 用户怎么点都不动 credits 字段，不写流水。
  - **退回的原子性**：在 db 上手动把某用户 credits 改 0，curl 并发 5 个 n=3 请求 → 最多只有 0 个能预扣到（5 个都拒绝）；改 9，5 个并发 n=3 → 最多 3 个能预扣到（一个用 3 张 = 9÷3），其余拒绝；不会出现「先扣 12 再说」的情况。
- `/image` 和 `/agents` 生图记录隔离：
  - 先在 `/agents` 并行模式跑出 3 张图（每张走 agent 流程，会写一条带 `agentId` 的 generation 记录）。
  - 再进 `/image`，左侧记录列表**只应**看到从 `/image` 工作台 / 画布发起的记录，**不应**出现刚才在 `/agents` 跑的 3 条。
  - 反过来：在 `/image` 跑出 2 张图（写带 `agentId=""` 的 generation 记录），点 `/agents` 工作区的「生成记录」按钮打开 Drawer，**只应**看到角色工作台的记录，**不应**出现 `/image` 那 2 条。
  - DevTools Network 看 `/image` 发的 `/api/generations` 请求 query string 应带 `excludeAgent=1`；`/agents` Drawer 发的请求带 `hasAgent=1`。
  - 越权防护不变：用账号 A token 调 `/api/generations?excludeAgent=1` 拿到的是 A 名下的非 agent 记录，不会泄漏 B 的。
- 流水线刷新后自动恢复：
  - 在 `/agents` 流水线模式跑一条 3 步流水线，等第 1 或第 2 步进入「运行中」状态时**刷新页面**。
  - 页面重新加载后，应该在 1-2 秒内（cache 拉回 + scheduler 扫到）自动接管这条 run：pill 短暂闪一下「排队中」然后变回「运行中 N/M」，继续跑接下来的步骤。**不会再无限卡在 loading**。
  - DevTools Application → Session Storage 应看到 `infinite-canvas:pipeline-run-ownership:{runId}` 标记；跑完后自动清掉。
  - 多 tab 不互踩：Tab A 跑一条 run（updatedAt 持续刷新），Tab B 同账号打开 `/agents` 看到这条 run 是「运行中」**不会接管**（因为 Tab B 的 sessionStorage 没标记 + Tab A 持续更新 updatedAt < 5min）。Tab A 跑完后 Tab B 仍能看到结果。
  - 跨设备孤儿兜底：A 设备跑了一条 run 然后断电（极端），B 设备打开 `/agents` 5+ 分钟后会自动接管。短于 5 分钟内不接管（因为有可能 A 还活着）。
  - 全程不需要手动点「重试 / 续跑」按钮 — 用户的 mental model 就是「刷新后流水线继续跑」。
